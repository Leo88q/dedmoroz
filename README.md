# 🎅 Диспетчерская Деда Мороза — бот для MAX

Бот-сервис заказа Деда Мороза и Снегурочки на дом для мессенджера **MAX**,
с фирменной гарантией **«подстрахуй свой Новый год»**: у каждого оплаченного
заказа есть резервный артист, а при форс-мажоре бот автоматически поднимает
резерв и эскалирует ситуацию диспетчеру.

## Возможности

**Клиент**
- Пошаговая анкета заказа: дата/время → адрес → ребёнок → персонажи → бюджет → телефон (кнопка `request_contact`) → пожелания.
- Подбор 2–3 артистов по району, бюджету и занятости, выбор по карточкам (рейтинг, цена, описание).
- Оплата предоплаты по ссылке (заглушка; точка интеграции ЮKassa/Robokassa).
- Напоминание за день и чек-ин за час до визита: «на месте / опаздывает / не приехал».
- Кнопка форс-мажора → мгновенный запуск резервного артиста.
- Оценка артиста после праздника, вопрос диспетчеру из бота.

**Артист**
- Регистрация в боте (имя, районы, цена, программа) → модерация диспетчером.
- Офферы заказов с кнопками «беру / откажусь», подтверждение резерва, SOS-запросы при форс-мажоре.
- Рейтинг по оценкам клиентов.

**Диспетчер**
- `/admin` — панель: модерация, активные заказы, форс-мажоры.
- `/artists` — заявки артистов с кнопками «одобрить / отклонить».
- `/orders` — активные заказы, `/events` — журнал событий.
- `/reply <user_id>` — ответ клиенту; ручное назначение артиста при эскалации.
- Мгновенные уведомления: новый заказ, новая заявка артиста, форс-мажор, эскалация.

## Архитектура

```
[Клиент в MAX] ⇄ [Бот (этот сервис)] ⇄ [SQLite/PostgreSQL]
                        │
                        ├─→ уведомления артистам (офферы, SOS)
                        └─→ уведомления диспетчерам (модерация, эскалация)
```

- `bot/maxapi.py` — тонкий клиент MAX Bot API (long polling, `/messages`, `/answers`) + fake-клиент для тестов/демо.
- `bot/db.py` — слой данных SQLite (совместим с переносом на PostgreSQL).
- `bot/router.py` + `bot/handlers_*.py` — маршрутизация обновлений и FSM-сценарии.
- `bot/services.py` — бизнес-логика: matching, резерв, форс-мажор, эскалация, напоминания.
- `demo.py` — консольное демо без токена.

## Быстрый старт

### 1. Демо без токена (локально)

```bash
pip install -r requirements.txt
python demo.py --script     # автоматический прогон полного сценария
python demo.py              # интерактивный режим (играете за всех ролей)
```

### 2. Настоящий запуск в MAX

1. Создайте бота: платформа [business.max.ru](https://business.max.ru/self) → **Чат-боты** → скопируйте токен (или через бота «MAX для бизнеса»).
2. Настройте окружение:

```bash
cp .env.example .env
# впишите MAX_BOT_TOKEN и DISPATCHER_IDS (свой user_id узнаете командой /id в боте)
```

3. Запустите:

```bash
pip install -r requirements.txt
python -m bot
```

Для запуска из РФ используйте `MAX_API_BASE=https://platform-api2.max.ru`
и установите сертификат Минцифры (см. dev.max.ru).

### 3. Docker

```bash
docker build -t dedmoroz .
docker run -d --env-file .env -v dedmoroz-data:/data dedmoroz
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MAX_BOT_TOKEN` | токен бота MAX | — (обязательно) |
| `MAX_API_BASE` | базовый URL Bot API | `https://platform-api.max.ru` |
| `DATABASE_PATH` | путь к SQLite | `./dedmoroz.db` |
| `DISPATCHER_IDS` | user_id диспетчеров через запятую | — |
| `DISPATCHER_CODE` | код для `/admin <код>` | `dedmoroz` |
| `PAYMENT_BASE_URL` | база ссылки оплаты | заглушка |
| `BACKUP_RESPONSE_MINUTES` | время на ответ резервного при форс-мажоре | 15 |
| `OFFER_RESPONSE_MINUTES` | время на подтверждение заказа артистом | 60 |
| `BUSINESS_TZ` | часовой пояс компании | `Europe/Moscow` |

## Как устроен «подстрахуй свой Новый год»

1. После оплаты бот автоматически назначает **резервного артиста** (лучший свободный на тот же слот, кроме основного) и просит его подтвердить готовность.
2. В день праздника клиент получает чек-ин с кнопками. «Не приехал» → заказ уходит в `force_majeure`, резервному летит **SOS-оффер с таймаутом** `BACKUP_RESPONSE_MINUTES`.
3. Резервный принял → клиент и диспетчер узнают, что праздник спасён. Не ответил/отказался → **эскалация диспетчеру** с кнопками ручного назначения свободных артистов или возврата денег.

## Тесты

```bash
python -m pytest tests/ -v
```

Покрыто: полный happy-path клиента, matching (район/бюджет/занятость), отказ
артиста, форс-мажор со спасением резервным, эскалация при молчании резерва,
ручное назначение диспетчером, напоминания, вопрос-ответ диспетчера.

## Правовые заметки (РФ)

- **152-ФЗ**: в заказе — персональные данные ребёнка (имя, возраст). Храните БД
  на серверах в РФ, минимизируйте данные, добавьте согласие родителя в `/start`.
- Оферта с правилами форс-мажора/возврата; договоры с артистами (самозанятые/ИП).
- Оплата — через российский эквайринг (ЮKassa, Robokassa): замените заглушку
  `PAYMENT_BASE_URL` + подтверждение `pay:done` на вебхук провайдера.

## Ограничения MVP и roadmap

- Long polling подходит для разработки; для продакшена переведите бота на
  Webhook (`POST /subscriptions`, см. dev.max.ru).
- Фото/видео-визитки артистов: загрузка через `POST /uploads` (точка расширения — анкета артиста).
- SQLite → PostgreSQL: слой данных изолирован в `bot/db.py`.
- Веб-админка (FastAPI + React) вместо чат-команд диспетчера.
